### 3. 关键技术判断

1. **文档必须写"null 字段不输出"这一条**。项目启用了 `default-property-inclusion: non_null`，实测确认：创建类日志**没有** `fromStatus` 字段、未指派的工单**没有** `assigneeId` 字段。若不写明，前端按"字段一定存在"取值会踩空。
2. **三块横切说明不是"加分项"而是必需项**：不写「HTTP 恒 200、业务结果看 code」，读者会把 `10001` 当成 HTTP 错误；不写状态机矩阵，读者无法理解"为什么这个关闭请求被拒绝"。

## 发现的问题

### 1. `spring.jackson.date-format` 对 `LocalDateTime` 无效（重要）

`application.yml` 中配置了：

```yaml
spring:
  jackson:
    date-format: yyyy-MM-dd HH:mm:ss
```

但实测响应是 **ISO-8601**：`"createdAt": "2026-09-23T17:54:36"`（`T` 分隔）。

原因：`spring.jackson.date-format` **只作用于 `java.util.Date`**；`LocalDateTime` 由 Jackson 的 `JavaTimeModule` 处理，默认按 ISO-8601 序列化，不受该配置影响。

**这是本项目第 2 次遇到「配置写了、看着生效、实际没生效」**（第8天的 `spring.data.redis` 前缀是第 1 次）。两者的共同点是：写错或不适用时**不报错、不告警**，只能靠实测发现。

**连带影响**：第7天验收单里记录的证据是 `createdAt=2026-09-20 19:46:22`（空格分隔），与本次实测的 ISO 格式不一致。需要确认是当时记录时做了格式化，还是记录有误——**以实测为准**，验收单该行建议加注更正说明。

### 2. Docker 引擎第 5 次中断（本次影响较大）

表现：服务已启动但所有请求返回 `50000`，日志根因是 `CommunicationsException: Connection refused`（3306 与 6379 同时不可达）。

排查过程：`docker version` 报引擎不可用 → `wsl -l -v` 显示 **`docker-desktop` 发行版 Stopped** → 说明 Docker Desktop 的 GUI 虽在运行，但 **WSL2 后端虚拟机没起来**。等待约 5 分钟后自行恢复（期间命令行探测一律显示"不可用"，容易误判为 Docker 没启动）。

**经验**：判断 Docker 是否真的可用，不能看 GUI 是否打开，要看 `docker version` 能否返回 Server 版本；若报引擎不可用，再用 `wsl -l -v` 确认 `docker-desktop` 是否为 Running。

### 3. 采集过程中另一处环境问题

重启服务时发现 `mvn` 不在新终端的 PATH 中（项目内 Maven 的 bin 加在用户级 Path，Trae 新建终端未继承）。应对方式：在命令里显式 `$env:PATH += "...\apache-maven-3.9.16\bin"`。

### 4. 更新接口不写操作日志（延续第7天登记）

实测确认：更新工单后查询日志，仍只有 1 条 `CREATE`，没有 `UPDATE` 记录。已在文档「已知边界」中如实标注。

## 面试价值

1. **接口文档的"示例必须来自真实调用"**：手写示例容易把 `data` 写成 `null` 而不是"字段缺失"、把时间写成带空格的格式。真实采集暴露了 `date-format` 失效这个问题——如果手写文档，这个坑会被继续掩盖下去。
2. **一致核对的价值**：集合能跑通不代表它与文档、代码一致。本次核对发现集合名与描述已过时（还写着"第6天 5 个接口"），这类"文档腐化"在项目里很常见。
3. **排查环境问题的正确顺序**：请求全 `50000` → 查应用日志拿到根因（JDBC 连接被拒）→ 查容器状态 → 查 Docker 引擎 → 查 WSL 发行版状态。逐层向下，而不是一上来就重启应用。
