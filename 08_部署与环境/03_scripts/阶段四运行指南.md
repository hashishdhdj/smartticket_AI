# 阶段四实际运行入口

更新日期：2026-10-16。当前工程收口与Linux复现见[最新复现指南](20261016_工程复现与交付指南.md)。以下脚本已实现；都从项目根目录调用。普通启动默认为无模型演示，不会自动向量化。真实模式需自行配置并明确计费预算。

## 本机应用

```powershell
Set-Location 'D:\SmartTicket-AI'
& '.\06_项目源代码\ticket-service\start.ps1' -CheckOnly
& '.\06_项目源代码\ticket-service\start.ps1' -Mode offline-demo -Offline -Port 8080
```

首次构建去掉-Offline，联网下载Maven依赖；已有缓存才用-Offline。启动脚本固定应用工作目录，四个依赖缺失、不健康或超过期限均失败；CheckOnly不启动应用。JDK17优先读取有效JAVA_HOME，缺失/无效路径回退到项目安装包；Maven优先PATH再回退到项目目录。不会设置系统级环境变量。

新机器复制02_env/application-local.yml.example到源码resources下的application-local.yml，然后通过环境变量提供MYSQL_PASSWORD、REDIS_PASSWORD、POSTGRES_PASSWORD、RABBITMQ_PASSWORD及可选RABBITMQ_USER；应用变量MYSQL_PASSWORD与Compose .env的MYSQL_ROOT_PASSWORD保持一致。不要覆盖本机已有配置。既有开发库的迁移和随机演示账号仍由prepare-phase3.py准备。

## 独立阶段四集成环境

```powershell
python '.\08_部署与环境\03_scripts\prepare-phase4.py'
& '.\08_部署与环境\03_scripts\Run-Phase3Tests.ps1' -Offline -Profile unit
& '.\08_部署与环境\03_scripts\Run-Phase3Tests.ps1' -Offline -Profile integration
python '.\08_部署与环境\03_scripts\verify-test-profiles.py'
python '.\08_部署与环境\03_scripts\audit-knowledge.py'
```

prepare-phase4使用smartticket-stage4项目及compose-stage4.yml；独立端口MySQL13306、Redis16379、PG15432、Rabbit15673/15674，绑定127.0.0.1，独立命名卷，不设置固定container_name。首次初始化和重复执行均应用幂等SQL；专用测试vhost和DLX已配置。随机凭据只存.gitignore覆盖的.tmp/phase4.env与phase4-integration.properties，脚本不打印。移除这些文件但保留已初始化卷会导致凭据不匹配，应保持它们成套。

all为兼容原有开发环境的默认全套入口；integration明确使用隔离配置，unit不依赖Docker。新增测试必须纳入显式profile，verify-test-profiles会防止遗漏。AI_SMOKE=true时还必须给-AllowVendor和明确-Tests，防止误跑全部厂商用例。

## 故障与性能脚本

需先打包JAR，并在调用Python前使JAVA_HOME指向JDK17：可dot-source Build-Environment.ps1。stage4-fault-smoke.py实际停启独立Rabbit/MySQL、重启自建应用；stage4-perf.py使用.tmp/phase4-clean目录中的构建JAR。它们会写合成数据，并在finally停止自己的Java进程；故障脚本恢复隔离依赖，不操作开发容器。

故障冒烟目前覆盖broker停机时创建及补发、DB停机时创建拒绝及恢复、PENDING任务跨应用重启；早期报告的覆盖边界以当时为准；后续高级故障与最终核查报告另行记录，不将早期冒烟当作全部故障覆盖。性能为同机暖缓存单工单详情，不能声称生产容量。
