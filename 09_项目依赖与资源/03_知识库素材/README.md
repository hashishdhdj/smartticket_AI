# RAG 知识库素材

本目录是 `01_项目说明/项目章程.md` 阶段2 交付物表中「RAG知识库素材」的**登记位置**。

## 为什么这里没有语料正文

语料的**权威位置在源码的 classpath 里**（`06_项目源代码/ticket-service/src/main/resources/knowledge/`），
本目录只做索引与说明，**不存放第二份副本**。

理由与项目里 SQL 脚本的处置一致（见 `06_项目源代码/` 下的建表脚本说明）：
两处都放正文，改一处忘一处就会漂移，而"哪一份才算数"在故障时是要命的。
应用启动只读 classpath，因此以 classpath 为唯一权威位置。

## 语料性质（必读）

**全部为演示语料，不是真实业务数据。**

其中04/05按当前项目代码核对，其余文件描述模拟客服平台，短信、订单、支付、附件等不代表项目已实现功能。模拟性质已加入各小节，以免文件前言被切分器排除后丢失范围说明。逐节登记见knowledge-sources.json，审查记录见阶段四资料登记与审查.md。

语料正文已修订，不等于向量索引已更新。当前尚未重建嵌入索引或用开发集复核阈值0.66；正式RAG效果评估前必须完成这些步骤。

本项目没有可用的真实 FAQ 与历史工单数据。为验证 RAG 链路（切分 → 向量化 → 检索 → 融合）
能够真正跑通并评估效果，必须有可检索的文本；因此这些语料是**按通用客服知识构造**的。

**请勿**当作生产知识库内容使用，也**不要**在文档里描述为"真实数据"。
将来接入真实 FAQ 时，整体替换 `knowledge/` 目录即可——切分与检索代码不依赖具体内容。
