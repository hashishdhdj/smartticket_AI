# G2经验卡与去重：完成说明及操作指南

日期：2026-10-23。状态：**第二步G2已实现并通过本地验收**。维护代码在`D:\SmartTicket-AI\.workspaces\review`，根目录同名文件为阅读副本。

## 1. 现在多了什么能力

G1相当于保存客服的原始工作记录。G2则把选定记录整理成格式统一的“经验卡”：遇到什么问题、适用于什么条件、按什么顺序操作、哪些办法失败、哪些情况不能照做，以及依据在哪里。

这里的整理使用已准备的AI合成结构字段，由Java校验和规范化；没有新调用模型从任意对话中自动提取事实，也没有训练DeepSeek。经过审核的卡已能沿用现有文本RAG索引与检索，但图节点、关系和Agent图谱工具仍属于后续G3/G4。

| 新能力 | 已实现行为 |
|---|---|
| 独立经验草稿 | 可以保存待核实经验，不要求先解决或关闭工单 |
| 精确去重 | 完全相同的内容共用一张卡，不重复生成结构；各工单的原文与反馈来源独立保留 |
| 保留关键差异 | 不删除否定词、数字、版本、步骤顺序；“原手机号可用”和“已停用”不会合并 |
| 近似提示 | 仅管理员可见有限的名称相似提示，不直接合并，不冒充语义识别 |
| 正反依据 | 失败原文不能作为成功步骤；纠正记录必须保留原错误和反例 |
| 已有知识复用 | 同卡已有审核、索引和健康依据时返回可复用来源提示，不新增审批或业务写操作 |
| 结构与文本版本 | 候选revision、卡片哈希、发布文本哈希、原始来源一起绑定，不允许只改文本而留下旧结构 |
| 失效与修订 | 正向依据新增失败反馈后新检索先屏蔽；撤回、换卡、重新审核保留历史版本 |

## 2. 关键实现

新增三个MySQL表：

- `experience_card`保存不可变的规范化结构和模板文本。
- `experience_submission`保存每次贡献来自哪张工单、哪些原始记录，以及准备时的反馈快照。
- `knowledge_experience_version`绑定candidateId＋revision、cardHash、publicationHash和来源提交。

内容经过保守规范化后计算SHA-256，由数据库唯一索引处理并发去重。条件等集合可以精确排序去重，操作步骤保留顺序和重复项。它能保证相同输入稳定识别，不保证两种不同说法在语义上相同。

保存经验卡不会修改工单状态。发布时需要既有工单解决记录生成DRAFT候选，再由管理员把同工单的卡绑定到候选并审核。待核实的退款问题可以一直保存为草稿；验收中的显式解决操作仅用于合成工作流测试，不表示真实退款已完成。

审核时重新检查结构、文本和反馈；结构版本、候选变更、审计、索引任务与Outbox在同一MySQL事务内提交。绑定与审核先锁工单再锁候选，并读取等待期间已经提交的最新结构，避免并发时绕过新绑定。

审批生成的正文包含适用范围、条件、正向步骤、禁止条件、失败反例和待验证假设。通过既有RabbitMQ和本地BGE-M3写入PG文本索引。检索仍按当前知识状态与版本检查，不改变RAG门槛、角色权限或Agent业务操作权限。

首版只接受明确标记的合成共享演示资料。REFERENCED_DEMO是资料编写者的待审核标签，不是机器证明事实正确；UNVERIFIED不能发布。未接入真实支付的范围被单独保留并强制待核实，不能通过换标签将“尚不清楚几点到账”变成成功退款知识。

