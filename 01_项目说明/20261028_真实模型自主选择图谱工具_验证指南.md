## 与已有G5对照的区别

G5的真实36次调用是把A/B/C证据交给模型比较回答，没有证明模型自主选择工具。本次保留原生Agent的系统提示词、完整只读工具定义和运行限制，由真实模型决定是否检索一线经验。用户问题不点名工具，不传强制tool_choice，也不伪造工具结果。

真实执行链：用户问题 → Java AgentService → DeepSeek返回工具名与参数 → Java调用实际工具 → MySQL/PG来源与权限校验 → tool_call_id对应的结果回传DeepSeek → 模型生成最终JSON → Java最终来源和版本校验。

这符合[DeepSeek官方Tool Calls流程](https://api-docs.deepseek.com/guides/tool_calls/)：模型选择函数，应用程序执行并回传结果，模型再生成答复。本项目实际执行函数的仍是Java服务。

1. AG01：原手机号可用时，查询已审核的一线密码重置经验。要求自主选择经验检索，正确说明条件、步骤、禁止情况和演示范围。

4. AG04：没有实际退款记录时，不承诺具体到账时刻。
5. AG05：撤回EXP01后重新问AG01，不能再检索或引用被撤回来源。可使用仍有效的其他来源，不要求强行拒答。

使用三条已冻结的合成经验EXP01、EXP10、EXP05和随JAR发布的现有知识资料，不使用真实客户信息。每次使用独立随机演示身份、消息命名空间和新建PG测试数据库；退出时只清理本次拥有的数据。

## 如何判定完整闭环

仅看到工具名不算完成。正例需同时满足：真实模型选中searchExperienceGraph；Java实际执行成功；后续真实模型请求携带对应tool_call_id的结果与非空图谱事实；最终答案引用实际送达模型的图谱sourceId；服务端返回SUCCEEDED且无人工升级。条件是否用对、是否编造办理结果另由AI辅助逐条审阅，不冒充人类评分。

普通文本、缺少事实和撤回场景另按各自目标评分，不能把“没有调用图谱”一律视为失败。本批材料此前用于开发，属于已知问题的定向回归，不能当盲测或整体成功率。
