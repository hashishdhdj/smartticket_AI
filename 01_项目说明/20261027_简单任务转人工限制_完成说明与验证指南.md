# 简单任务转人工限制：完成说明与验证指南

日期：2026-10-27。工作副本：`D:\SmartTicket-AI\.workspaces\review`。本页说明G5复核后新增的回答去向约束；不是修改冻结G5成绩，也不是新的真实模型效果评估。

## 改了什么

之前needHuman容易混用：“答案没有依据”“后续业务涉及人工”“资料只是演示”都可能被模型标成true；Agent又会把未完全成功理解为需要人工。本轮将回答、澄清和人工处理分开，减少把简单咨询交给管理员。

| 问题 | 现在应如何处理 |
|---|---|
| PUT只改标题会不会保留描述？ | 资料说明全量更新，就直接解释清空风险，不转人工。 |
| Outbox的SENT能说明AI分析成功吗？ | 直接解释投递成功和分析完成的区别，不转人工。 |
| 知识已经审核，为什么还查不到？ | 资料有审核/索引区别和核实步骤时，直接解释；不能仅因没列具体命令而转人工。 |
| 我的账号有问题，怎么办？ | 先问具体报错等必要信息；追问不需要管理员接手。 |
| 管理员审核是怎么回事？ | 解释流程不等于申请实际审核，不因出现“管理员”就转人工。 |
| 请确认这笔退款已经到账 | 缺少真实处理记录，说明具体缺失事实，保留人工处理出口。 |

新模型输出新增handoff对象。Java统一检查原因白名单、状态与needHuman是否一致，以及是否给出具体阻塞说明。不接受只有“转人工”而没有原因的标记。若判定不合规，最多纠正一次；仍不合规则待澄清并保留来源，不冒充回答成功。

Agent纠正不再开放工具，沿用4次模型/6次工具/12000保守Token/60秒默认总限制。RAG最多2次生成调用，仍经过已有预算与超时检查。真正故障、伪造引用、版本过期、权限限制和检索0.55门槛继续有效；没有赋予模型直接指派、关单或发布知识的权限。

## 调用方怎么看结果

- `nextAction=ANSWER`：展示有依据的答复。
- `nextAction=ASK_USER`：展示追问或待补充信息，不分配人工。Agent状态为WAITING_INPUT，needHuman=false。
- `nextAction=HUMAN_SUPPORT`：显示具体原因；这只是处理信号，不表示管理员已经接手。
- `nextAction=CONFIRM_ACTION`：Agent已经生成待确认提案，仍需独立确认接口执行。

只有关键业务事实缺失或真正需要人工办理时，模型才能请求人工。模型/工具/预算等真实故障仍有独立原因。新增字段不会覆盖工单状态，也不会让未完成的操作变成成功。跨请求继续沟通时，客户端仍须携带原问题和补充信息，本轮没有新增会话记忆。

完整枚举、兼容方式与返回字段见[API契约](../docs/api/handoff-policy.md)。
