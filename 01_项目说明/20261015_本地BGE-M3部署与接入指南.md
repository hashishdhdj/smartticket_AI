# 本地 BGE-M3 部署与项目接入

日期：2026-10-15。目标：本机负责向量化，DeepSeek继续负责生成回答与Agent决策。

## 部署方式与费用

复用已有Docker Desktop，不额外安装Windows版Ollama。Ollama镜像与BGE-M3模型均需首次联网下载；约1.2GB仅指模型，镜像还需要额外下载与存储空间。本地调用没有厂商按次费用，消耗本机计算资源和电力。DeepSeek云端调用仍计费，原首批¥10预算继续有效。

本机检查：物理内存约32GB，Docker可用内存约16GB，D盘可用空间约110GB。先采用CPU运行，实际响应速度以预检为准，不承诺GPU加速。

## 本轮自动执行状态

本轮已启动单一后台部署流程，不要同时重复执行安装/验收脚本。它会下载运行环境和模型，完成真实1024维预检、隔离库校准、日常开发库向量更新及Java检索接口验证，全程关闭云端回答。进度以本机状态文件为准：

```powershell
Set-Location 'D:\SmartTicket-AI'
Get-Content '.\.tmp\phase4-local-deployment-state.json'
```

`RUNNING / WAITING_IMAGE`表示仍在下载镜像；`DOWNLOADING_MODEL`表示下载模型；之后依次检查两个数据库；只有`PASS / COMPLETE`才代表本地模型接入通过。`FAILED`表示已停止，保留失败阶段；此时先检查`.tmp/phase4-ollama-image.log`、`phase4-ollama-install.log`、`phase4-ollama-verify.log`或`phase4-ollama-development-verify.log`中的对应日志，再恢复。

保持Docker Desktop运行和电脑联网，不要休眠。首次部署的镜像下载量大于模型的1.16GB，网络慢时需要较长时间。后台流程已经完成日常开发库验收时，直接用第三步的real-model命令启动即可，不必重复重建。若需在没有现有任务的新环境重新完成整套流程，可运行：

```powershell
& '.\08_部署与环境\03_scripts\Complete-LocalEmbedding.ps1'
```

以下分步命令用于理解和独立重试；有同一任务运行时不要并行启动。

## 第一步：下载并启动

启动Docker Desktop，等引擎就绪。在PowerShell执行：

```powershell
Set-Location 'D:\SmartTicket-AI'
& '.\08_部署与环境\03_scripts\Setup-LocalEmbedding.ps1'
```

脚本依次下载官方Ollama镜像、启动本地服务、下载bge-m3:latest、调用真实嵌入接口并校验1024维。成功会显示PASS并保存不含向量正文/密钥的预检证据。中断后可重复运行，已有完整镜像层和模型数据可复用；若模型下载尚未完成，不要使用-SkipPull。

模型保存在Docker命名卷`smartticket-embedding_ollama-models`，实际磁盘位置由Docker Desktop的数据盘设置决定，并非直接存储在项目D盘目录。服务仅映射`127.0.0.1:11434`，无需外部API Key，禁用Ollama云功能。卷可在容器重建、Docker重启后保留；不要执行`down -v`或清理该卷。

检查命令：

```powershell
docker compose -p smartticket-embedding -f '.\08_部署与环境\01_docker\compose-ollama.yml' ps
docker compose -p smartticket-embedding -f '.\08_部署与环境\01_docker\compose-ollama.yml' exec -T ollama ollama list
Invoke-RestMethod 'http://127.0.0.1:11434/api/version'
```

## 第二步：项目真实接入验收

```powershell
& '.\08_部署与环境\03_scripts\Verify-LocalEmbedding.ps1'
```

脚本选择本地provider，准备独立阶段四中间件，运行Java单元测试并打包，通过实际Java加载器导出32条切片，启动隔离应用，在15432端口的测试PG库重新生成向量。逐条核对模型、1024维和正文哈希，再使用历史32题开发集核查阈值。对话模型关闭，不调用DeepSeek。

旧模型和新模型即使都是1024维，也不能混合检索。索引编排按模型名变化重新生成全部向量；原校准报告先归档，不能直接套用旧阿里云阈值。开发集调阈值不等于独立评估通过。

## 第三步：日常项目启动

第一次将本地模型接入日常开发库时，先启动只做本地检索的模式并重建该库索引：

```powershell
& '.\06_项目源代码\ticket-service\start.ps1' -Mode local-rag -EmbeddingProvider ollama -ReindexKnowledge -Offline
```

此命令使用日常开发中间件端口，区别于第二步的隔离测试库。等日志显示知识索引完成，确认实际写入32条且无失败，再测试检索。该模式关闭对话与异步AI消费者，返回的生成建议可能为空，应观察sources、confidence、degradedSources。

需要恢复完整AI回答时，按Ctrl+C结束上述Java前台进程，然后运行：

```powershell
& '.\06_项目源代码\ticket-service\start.ps1' -Mode real-model -EmbeddingProvider ollama -Offline
```

本地profile沿用应用默认阈值，具体效果以本地开发校准为准；有审查依据后再调整阈值。普通启动不自动重建索引。offline-demo仍关闭全部模型调用；local-rag才是“开启本地向量化、关闭云端回答”。首次缺Maven依赖缓存时去掉-Offline。

## 第四步：效果评估

本地校准完成后，在已有¥10预算内可重新评估：

## 停止与恢复

```powershell
docker compose -p smartticket-embedding -f '.\08_部署与环境\01_docker\compose-ollama.yml' stop
docker compose -p smartticket-embedding -f '.\08_部署与环境\01_docker\compose-ollama.yml' start
```

停止服务不删除模型。下载失败先检查官方Docker Hub/模型仓库网络；本项目不自动替换成未知镜像站。

参考：[Ollama官方Docker部署](https://docs.ollama.com/docker)、[嵌入兼容接口](https://docs.ollama.com/api/openai-compatibility)、[BGE-M3模型](https://ollama.com/library/bge-m3)。


## 本轮下载失败与DNS修复记录

首次失败位于DOWNLOADING_MODEL：Ollama v0.40.4返回`redirect target not allowed`，官方R2下载域名被系统/容器DNS解析成`198.18.0.159`。直接指定公共DNS仍返回该Fake-IP；不能据此断定用户使用了哪一种代理软件。

已增加`prepare-ollama-dns.py`：仅检测到198.18.0.0/15时，通过Cloudflare HTTPS DNS查询这个确切的官方下载域名，校验返回值均为公网地址后，为Ollama容器生成临时extra_hosts覆盖。不关闭TLS证书验证，不使用--insecure，不修改Windows系统DNS，也不改业务数据库。每次Setup重新查询；原始答案与TTL记录在`.tmp/ollama-public-dns-evidence.json`。未检测到Fake-IP则使用系统DNS，不应用旧覆盖文件。

恢复流程已实际进入模型文件传输，区别于此前仅拉取manifest。模型仍需完整下载与校验，不能据此标记整个部署通过。后续跨机器若不再存在Fake-IP，Setup会移除当前启动配置中的此项覆盖；操作前确认没有同一流程正在运行。DNS修复的3项本地测试通过（无网络调用），包含正常DNS、受限容器映射及非公网答案拒绝。

Complete入口新增文件锁，拒绝两个部署流程同时写进度或索引。镜像已缓存时不再拉取新版本，恢复使用现有镜像和持久模型卷。
