# G4：Agent图谱检索与来源校验

日期：2026-10-23。维护副本：`D:\SmartTicket-AI\.workspaces\review`。本轮实现只读图谱工具和Agent来源闭环，不训练基础模型、不新增自动指派/解决/关单权限。

## 1. 第四步具体做了什么

第三步解决了“经验怎么保存成真正的图谱”。第四步把图谱接到了Agent的工具箱：

```text
用户提出问题
→ 模型选择searchExperienceGraph并给出检索词
→ Java使用现有向量＋关键词检索定位经验
→ Java校验审核状态、版本、图文哈希、回执和实际图证据
→ 返回同一来源的条件、步骤、禁止条件、反例及有限关系路径
→ 模型据此组织建议
→ Java检查引用，复核来源仍有效，附上演示范围与真实来源
```

这就是本项目中“Agent学习一线经验”的含义：下一次处理请求时检索新发布的外部知识，无需重新训练DeepSeek。知识增加不改变操作权限。

管理员审核的是经验发布版本。已审核共享经验可以被后续请求反复读取，不需要每个客户问题都重新请示管理员。员工内部记录仍受原来的工单权限约束，普通用户只读发布后的共享演示知识。

## 2. 新增及修改内容

| 位置 | 职责 |
|---|---|
| ExperienceGraphReader | 验证MySQL审核/健康/索引版本、不可变经验、图回执、当前模型和实际PG图快照 |
| ExperienceGraphSearchService | 混合检索定位来源，按来源组织最多2跳关系，返回条件、步骤、反例和证据 |
| AgentTools | 注册和分发searchExperienceGraph，校验参数、身份与工单标题读取权限 |
| AgentToolContext | 图工具的来源收集、整份上下文裁剪、范围保留及重复来源处理 |
| AgentService | 识别两类知识工具，追踪实际送达来源，在最终回答前重新核对图来源 |
| AgentAnswer | 校验引用只能来自真实工具结果，附加合成演示和未核实效果说明 |

Agent提示版本更新为`agent-v3.2-graph`。不引入新的Python检索服务或图数据库，仍由Java读现有PG图表。没有新增DDL，使用G1–G3迁移即可。

工具严格接受：

```json
{"query":"原手机号仍能收短信，演示账号忘记密码应怎样处理？"}
```

返回sourceId形如`resolved-ticket/{candidateId}/v1.md#0`；关系和节点ID不能当作来源引用。模拟短信规则必须保持“模拟规则、非SmartTicket实际短信能力”的范围。

## 3. 防止哪些错误

1. **查到过时经验**：审核前、撤回后、工单删除后、新的失败反馈出现后，不再提供相应图证据。图文版本、哈希或回执不符时也不放行。
2. **两份经验混成一个办法**：每份经验单独返回完整条件和步骤，不沿共享节点跨来源拼接。
3. **裁剪后丢失“不可以”**：给模型的图来源内容总额度为6500 UTF-8字节；一份经验整体纳入或整体省略，不截断条件和反例。被省略的来源不能引用。
4. **把错误做法推荐给用户**：失败反例、禁止条件和待验证假设分别保留。提示词要求前提不明先核实，不能把“可能原因”说成确诊。
5. **伪造引用或引用已撤回知识**：只接受实际送达模型的sourceId；最终输出前再次核验引用的图版本和健康情况。失效时返回PARTIAL/STALE_GRAPH_SOURCE。
6. **检索后冒充已经操作成功**：图工具只读，工单内容和状态不会因此改变。原指派提案仍需独立确认。

检索最多检查6个不同动态来源、返回2份经验；每份最多48节点、64关系、128条证据、2跳。沿用既有Agent调用、Token和时限预算，没有新增高相似度拦截门槛。图不可用时提示可查询普通文本知识或转人工，原工单流程继续可用。

版本与引用检查不等于自然语言语义完全正确；本轮不据此宣称所有回答都正确，或管理员真实工作量已下降某一比例。

## 4. 默认开关与启用

`smartticket.experience.graph-search-enabled`默认false。使用图工具还需同时开启experience.enabled、cards-enabled、graph-index-enabled及knowledge.enabled，并先完成已有迁移。关闭图检索，原searchKnowledge仍可用。

本机演示脚本自动为临时服务生成隔离配置。不要把忽略目录中的真实密钥复制进公开配置，不要在保留的原根目录启动旧源码。

## 6. 如何理解演示结果

这次Java、Spring AI的HTTP工具协议、RabbitMQ、MySQL、PG和本地BGE-M3都真实运行；只有对话模型使用脚本自己启动的127.0.0.1离线替身。替身读取真实tool消息，把条件与步骤组合成固定格式文字，不代表DeepSeek真实生成质量。

演示依次核验：未发布时查不到；审核索引后能返回条件、顺序步骤、路径和真实引用；伪造来源被拒绝；模型组织回答期间撤回知识后，最终引用被拦截；撤回后的新检索也查不到；工单状态和内容没有被工具更改。
