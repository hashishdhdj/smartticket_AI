## 二、自动化回归证据

```text
$ mvn clean test
[INFO] Tests run: 218, Failures: 0, Errors: 0, Skipped: 6
[INFO] BUILD SUCCESS
```

Skipped 6 = `AiRealVendorSmokeTest` 2 + `KnowledgeRetrievalRealVendorTest` 4（真实厂商调用，默认跳过）。

测试数演进（第4周）：**172 → 186（第5天 +14）→ 203（第6天 +17）→ 218（第7天 +15）**

本周新增/扩充的测试类：

| 测试类 | 用例数 | 覆盖 | 是否依赖 Docker |
|---|---:|---|---|
| `KnowledgeChunkerTest` | 14 | 小节切分、超长二次切分、重叠、硬切兜底、空文档 | 否 |
| `KnowledgeCorpusLoaderTest` | 6 | 语料加载、来源路径、小节数 | 否 |
| `EmbeddingServiceImplTest` | 7 | 分批 ≤10、维度校验、降级 | 否 |
| `KnowledgeIndexingServiceTest` | 5 | SHA-256 + model 双条件幂等 | 否 |
| `KnowledgeVectorIntegrationTest` | 4 | **真连 PostgreSQL**：写 vector 列、`vector_dims()`、`ON CONFLICT DO UPDATE`、`<=>` 与 `word_similarity` | 是 |
| `KnowledgeRetrievalServiceImplTest` | 12 | 四种降级各归其码、模型同源校验在调嵌入前、配置透传 | 否 |
| `RrfFusionTest` | 9 | 单路/双路融合、dense rank、去重、topN 截断、稳定排序 | 否 |
| `KnowledgeSearchServiceImplTest` | 5 | 两路都成功、向量路降级、双路降级、topN、空查询 | 否 |
| `KnowledgeRetrievalRealVendorTest` | 4 | 真实厂商：两路召回质量、门槛标定、融合对照 | 是（+需密钥） |

> 说明：融合与编排的两个测试类是**纯单测**，不连库、不调接口，可零成本随时跑：
> `mvn test -Dtest=RrfFusionTest,KnowledgeSearchServiceImplTest`
