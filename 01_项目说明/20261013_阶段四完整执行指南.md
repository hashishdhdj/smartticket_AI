## 0. 先确定执行原则

目标是交付可复现、有真实效果证据、可解释的实习面试项目。保留现有模块化单体，不新增技术栈凑关键词。当前工程基线为上次321项测试中的312项成功、9项真实厂商跳过；之后新增功能必须有相应验证。

## 2. 建立独立复现和CI（4A收尾、4B）

### 步骤4：干净环境复现

准备独立交付目录，包含明确的源码与文档版本，不复制target、.env、local配置、数据库备份、Maven缓存或portable安装包。用新生成凭据和配置样例运行。若尚未形成commit，先检查完整交付文件清单，不能仅git archive HEAD导致漏掉未跟踪的阶段三实现。

部署开发Compose含固定container_name和端口，**只更换-p项目名无法隔离**。阶段四要新增独立测试Compose：去固定容器名，独立卷/库/vhost、可配置宿主端口，或在隔离网络中直接连接服务名；用短目录路径解决Java本地协议测试的临时路径限制。

完整复现顺序：安装JDK17/Maven/Python/Docker → 从样例生成配置 → 启动依赖并确认四服务healthy → 新库初始化或增量迁移 → 设置Rabbit用户权限/测试vhost/DLX策略 → 首次联网构建 → 无模型启动 → 合成数据接口验收 → 测试 → 停止应用。失败记录准确步骤和日志，不删除开发数据卷“重试”。

验收：无作者机器私有文件也能完成，所有缺失依赖都有说明，明确应用在宿主机运行而非Compose应用容器。保存版本、命令、耗时、退出码和结果；镜像下载时间与应用启动时间分别记录。

### 步骤5：测试分层与CI

建立Maven profile或JUnit标签，对实际测试类逐个分类；不是仅把文件名叫Unit就能保证无数据库依赖。

| 层 | 默认环境 | 运行要求 | 通过定义 |
|---|---|---|---|
| unit/protocol | 无厂商密钥；本地HTTP替身按依赖分类 | 快速模型/解析/工具保护测试；有真实DB依赖的协议类归integration | 数量、失败、错误、跳过均报告 |
| integration | 独立MySQL/Redis/PG/Rabbit；替身模型 | 迁移、事务、MQ、版本、缓存、Agent权限/确认；准备专用vhost | 新环境全通过，保留Surefire artifacts |
| vendor-eval | 手动开启、真实厂商、受控预算 | 单独运行评估，不进入普通PR流水线 | 无意外跳过，全体结果和用量记录 |

CI交付：.github/workflows中构建/测试工作流（如最终托管非GitHub则用对应CI），固定JDK17、依赖缓存、明确工作目录，容器health与迁移准备，上传去敏日志、失败用例和报告。CI使用临时测试密码，不嵌入本机密钥。修改源码后至少重跑受影响层，发布前跑完整无厂商集成回归。

本地成功只记本地；未上传仓库或未运行远程CI时，不写“CI已通过”。创建工作流文件不等于CI验收。当前没有可直接运行的阶段四CI或新profile，本步骤需要实现。

### 步骤6：角色与API核对

更新旧CRUD Postman集合：增加三种演示角色的环境变量、401/403/409/429、analysis查询、管理员幂等重放、Agent运行、人工确认与metrics。凭据仅在本地环境中填写，集合导出不带真实Token。

明确对象权限矩阵：SUBMITTER自己的工单、HANDLER指派给自己的工单、ADMIN全部。再逐项审核update/resolve/assign/logs/analysis权限是否符合产品意图。请求体creatorId/operatorId不能伪造身份；保留字段校验和兼容原因要写清。

检查旧页面修改语义：当前服务端版本CAS防并发覆盖，未证明客户端持有旧版本也会被拒绝。决定是否增加expectedVersion；选择保留现状就写限制。不要在阶段四无需求地重做登录或权限平台。

## 3. 完成真实故障演练（4B）

前提：隔离Compose与合成数据准备完成；模型使用可控替身或规则模式，厂商调用为零。所有暂停/重启只针对新测试环境，开发smartticket-*容器保持运行。

| 演练 | 具体过程 | 观察/验收 |
|---|---|---|
| broker不可用 | 测试broker停止或切断连接；创建合成工单；记录工单/task/outbox；恢复broker | 创建仍成功，Outbox保留未发事件；恢复后SENT，任务达终态，同task仅一份结果 |
| DB不可用 | 投递已准备消息；短时切断测试DB；观察listener暂停/恢复；恢复DB | 不ACK未提交结果、不无限热重排；恢复后任务继续或明确FAILED；记录暂停与恢复日志 |
| 应用重启 | 让任务在RUNNING/租约期间重启测试应用；再测试结果提交后的重复消息 | 租约到期后恢复；旧令牌不覆盖；重复投递无重复结果；记录是否发生重复模型调用 |
| Redis不可用 | 测试Redis不可用时更新工单；恢复后观察补偿 | 数据库写入有效，失效事件保留/补偿；不返回旧版本缓存 |
| AI故障 | 本地HTTP替身返回超时、429、无效JSON、401 | 按实际错误分支重试/兜底/停止；次数和终态可解释，不将RULE计作模型成功 |

保存每个场景的ticketId/taskId/runId、故障开始/恢复/终态时间、注入方式、数据库前后状态、相关日志和重复结果计数。Outbox持续退避与分析最多3次重试是两种机制；长期故障下PENDING可以是设计行为，不应伪造FAILED。

DB基础设施恢复失败、消息丢失、人工字段被覆盖、重复结果或权限越界：停止收口，修复后重演对应场景。重复厂商计费并未被严格消除，报告应说明“结果幂等不等于外部调用恰好一次”。

## 4. 数据集与真实效果评估（4C）

### 步骤7前置：知识库审查与资料补充（4C0，约1—2小时起步）

**先修正资料，再补缺口，最后冻结并出独立评估题。** 现有7份文件、26个小节全部为演示语料，不是真实客服数据。本项目不强制收集私有真实工单，也不以新增条数为验收目标。

1. **逐节审查**：账户、支付、功能异常、工单流程分别检查适用场景、处理步骤、转人工条件、来源与当前规则一致性。优先处理04-工单流程与通用问题.md：状态分支、重开入口、UPDATE审计、缓存说明须按当前代码/API核对，不能把枚举允许的转移等同于已开放接口。
2. **列缺口再收集**：优先补项目自身的对象权限、AI建议与人工字段、任务状态、转人工和确认指派说明。对于账户/支付等模拟业务，明确模拟平台边界；可用官方帮助资料作参考，但其他平台的退款时限不能直接当本项目承诺。真实记录只取已获使用权限且脱敏的已解决案例；没有合适资料就保留模拟性质与人工处理边界。
3. **建立登记**：在09_项目依赖与资源/03_知识库素材下维护资料登记表，逐项写来源位置、性质（项目规则/模拟场景/公开参考/脱敏记录）、核对日期、适用范围、入库位置、审查状态。外部资料要记录具体页面和查阅日期；尚未查证的内容写待核对。不在该目录复制一份语料正文。
4. **整理入库**：正文唯一权威位置仍是src/main/resources/knowledge/faq与tickets，按现有#文档标题、##问答小节切分。每节建议150—500字，包含场景、步骤、限制/转人工条件；每节元数据在登记表中对应，避免长URL和登记内容污染检索正文。先复用现有小节，新增小节必须有明确覆盖价值。
5. **验证与冻结**：检查加载/切片、来源标题、重复内容及越界承诺；先做无费用格式和代码一致性验证，嵌入更新需按真实模型预算分批运行。记录语料SHA256、切片数、嵌入模型/维度/索引版本；不能预设新增后仍是26条切片。阈值0.66基于旧语料，变更后用开发集重查，不用保留集调参。

4C0完成标志：关键错误已校正；每个入库小节有可追溯登记；四类场景覆盖缺口有补充或清楚的拒答/转人工边界；代码与资料互相不矛盾；切片验证和语料版本记录齐备。使用模拟资料不妨碍工程验收，但不能声称真实客户知识库已建成。

知识库与评估集保持独立：参考答案的事实依据应来自冻结知识库，但不能直接把保留集的问题和标准答案灌入知识库。资料不足的题用于拒答评估，不为通过考试临时补对应答案。

建议新增三个JSONL数据文件与评估说明到07_测试与质量/04_AI评估集，UTF-8。JSONL适合存储嵌套工具/证据标签；现有CSV保留为历史基线，不覆盖。正式跑前计算文件SHA256并记录语料、Prompt、配置和模型版本。

保留集只在冻结后评估；一旦看结果并据此调Prompt/阈值，该集合成为开发集，下一轮毕业结论要使用新的未见数据。参考答案需对照知识语料或确定业务规则逐项核对；作者确认标签后冻结，不能由待测模型自己决定标准答案。

| Agent正常任务完成率 | 正常题目标完成、必需工具参数正确、来源/日志真实、无未经确认写入 | ≥80%；逐题展示调用顺序和失败类型 |
| Agent安全不变量 | 未授权数据不泄露、危险工具不执行、模型不能代替人工确认；全体用例检查 | 0违规；任何违规先修复 |
| 稳定性 | 选择5题各跑3次，报告目标完成一致性与工具轨迹差异 | 单列实际结果，不混进独立样本数 |

旧README把“任一来源命中”叫Recall@3，阶段四统一称Hit@3；若标签列的是替代答案，这个名称更准确。只有列出多个必须找回的来源时，才能用“找回相关来源数/全部必需相关来源数”计算Recall@3。相似度0.66和RRF排序分都不是正确概率。

答案人工评分可用0/1/2：0错误/编造，1部分正确或依据不足，2必要事实齐全且依据成立；2分算合格。关键词用于提示遗漏，不能独立判正确。模型评审只做辅助，核心评分保留人工判定与引用依据。

### 步骤9：实现评估执行器并小规模试跑

阶段四要新增执行器；现有RagRetrievalEvaluationTest仅绑定旧CSV，不会自动评估新JSONL。执行器必须支持dataset、limit、模式和厂商调用上限；保存每题原始结果、tool轨迹、来源、耗时、usage/预留、错误、降级、人工评分；请求失败也落盘，结束输出实际分母。

先做零费用校验：字段完整、标签枚举合法、来源确实存在、题号唯一、角色/fixture有效、必需与禁止工具无冲突；用替身验证结果记录与汇总口径。

再做真实模型预检：核对所选厂商官方文档中的模型名、tool calling、JSON支持、端点和价格；记录核对日期，不照抄仓库旧注释当当前产品规格。检查密钥/余额、本地配置和知识索引版本；模型或嵌入版本/维度变化时不能复用不匹配的索引。

真实调用成本包含对话轮次、检索查询嵌入、首次语料向量化和稳定性重复。20条Agent、每条最多4轮，是最多80次应用模型轮次，还可能有额外嵌入；不是20次计费请求。SDK/网络重试和后台任务会改变次数，因此应用轮次上限不是最终费用保证。

采用分批预算：先1次对话与1次嵌入连通性，再3条Agent、3条RAG、3条分类试跑；确认日志和厂商用量后才跑正式集。初次试跑不必做重复稳定性测试。每批写清人民币上限、模型请求上限、最长运行时间；无余额或预算信息则保持真实评估待执行。现有dailyTokens=50000是保守预留，可能提前阻止整批Agent；不要为了跑完关闭保护，按用户/日期拆批并如实报告429。

现有单次真实对话冒烟可按下面命令显式选择一个方法，不开启全套厂商测试：

```powershell
Set-Location 'D:\SmartTicket-AI'
$ticketOldAiSmoke=$env:AI_SMOKE
try {
    $env:AI_SMOKE='true'
    & '.\08_部署与环境\03_scripts\Run-Phase3Tests.ps1' -AllowVendor -Tests 'AiRealVendorSmokeTest#realVendorCallSucceeds'
} finally {
    if ($null -eq $ticketOldAiSmoke) {
        Remove-Item Env:AI_SMOKE -ErrorAction SilentlyContinue
    } else { $env:AI_SMOKE=$ticketOldAiSmoke }
}
```

这条会收费，属于后续执行操作，本次准备未执行。测试可能因未配置/禁用而跳过；跳过不代表连通。不要设置AI_SMOKE=true后跑所有测试来做第一次预检。独立评估环境关闭async-enabled、record-tasks、index-on-startup等无关入口；最后做异步真实链路时另开单张合成工单专项。
