2026-10-23。状态：**第三步G3已实现并通过本地完整验收**。维护目录为`D:\SmartTicket-AI\.workspaces\review`，根目录同名文件为阅读副本。

## 1. 通俗理解：这一步做了什么

G1保存客服原始处理记录，G2把记录整理成经验卡。G3进一步把经验卡中的内容拆成真正存入数据库的关系：某类问题出现什么症状、需要满足什么条件、可以按哪些步骤处理、哪些办法是失败反例。

例如，“演示账号忘记密码”与“原手机号仍能收短信”之间保存REQUIRES关系，与“核实后设置新密码”之间保存处理关系。每条关系还携带来自哪张卡、哪个审核版本和哪份资料的证据，不能只看一条连线就把它当成无条件正确的结论。

现在图已经真实存在于PG数据库中，管理员可以通过后端接口核查。**Agent调用图谱检索工具尚未接入，那是下一步G4。** 目前没有训练模型，也没有宣称图谱已经提高了真实回答准确率。

## 2. 已实现的内容

| 内容 | 当前行为 |
|---|---|
| 真实节点与关系 | PG保存问题、症状、条件、步骤、结果、失败反例和待验证假设 |
| 逐条来源证据 | 每条关系绑定候选版本、卡片哈希、文本哈希、图哈希、字段位置、引用和编译规则版本 |
| 图文共同发布 | 文本向量、图目录、节点、边和证据在同一个PG事务内提交，失败一起回滚 |
| MySQL完成回执 | indexedRevision、图回执与任务完成在同一MySQL事务中确认 |
| 故障恢复 | PG成功但MySQL确认失败时补回执；文本已有向量但图缺失时补建图，不重复向量化 |
| 独立来源撤回 | 撤回一条经验只移除该来源证据，共用关系的其他支持来源继续有效 |
| 版本与迟到保护 | 撤回先隐藏，PG墓碑阻止旧INDEX/旧补建复活；修订保留历史回执 |
| 管理员验收入口 | 可查看当前有效图，或为已索引经验请求幂等补建；普通用户和处理人不能直接访问 |

假设使用HAS_HYPOTHESIS，失败反例使用HAS_COUNTEREXAMPLE，不混入正向处理步骤。结果节点保留“业务效果待核实（非独立验证）”，不会因为演示反馈写了成功就声称真实客户问题已解决。

## 3. 如何实现与保证一致性

新增PG四张表：`experience_node`、`experience_edge`、`experience_edge_evidence`、`experience_graph_publication`。新增MySQL `knowledge_graph_receipt`。迁移分别为MySQL08与PG03，没有改写已有迁移。

图由固定Java规则从规范化经验卡编译，不额外调用大模型抽取关系，不执行生成的代码。节点和边使用稳定哈希确定身份，保留否定词、数值、版本与步骤顺序。相同内容可以共用节点和关系，来源证据按candidateId/revision分别保存。

```text
已审核经验卡
→ 验证结构、文本、来源与健康反馈
→ 固定规则编译图
→ 必要时在事务外做本地BGE-M3向量化
→ 一个PG事务保存文本与图
→ 一个MySQL事务确认当前版本、图回执和任务完成
```

系统没有使用跨库分布式事务。两库之间仍可能出现“PG已提交、MySQL未确认”的窗口，但窗口中的图不会被当作READY返回；后台任务比较实际数据后补回执。事务故障和消息重复不会靠模型判断修复，由Java任务、版本围栏、哈希和真实数据库查询处理。

管理员接口返回READY前检查两库目录、回执和真实图行。审批撤回、源工单删除或正向依据新增失败反馈后，不再向新请求返回旧图事实。无证据的词表节点可以保留，但不能作为有效知识输出；不同经验的条件也不能随意拼接。

历史G2经验已完成文本索引时，可以通过图补建入口复用原向量、原INDEX任务和同一候选revision。补建记录独立重放审计，原有失败重试接口仍只允许FAILED，没有为了补建放宽旧接口。

## 5. 你可以怎样复跑

确认Docker引擎运行，Ollama已提供bge-m3:latest，勿与其他集成验收并行。当前维护副本已经生成验证包，可以直接运行：

```powershell
Set-Location 'D:\SmartTicket-AI\.workspaces\review'
$env:JAVA_HOME = 'D:\SmartTicket-AI\09_项目依赖与资源\02_下载链接与校验\安装包\JDK\jdk-17-runtime\jdk-17.0.20.1+1'
$ticketJava = Join-Path $env:JAVA_HOME 'bin\java.exe'
python '.\08_部署与环境\03_scripts\verify-staff-experience.py' --with-cards --with-graph --java $ticketJava
if ($LASTEXITCODE -ne 0) { throw 'G3验收失败，请保留报错' }
$graphResult = Get-Content '.\.tmp\g3-experience-graph.json' -Raw -Encoding UTF8 | ConvertFrom-Json
$graphResult | Select-Object status,stage,graph_built,graph_database_counts,revision_history,vendor_calls,own_records_cleaned
$graphResult.graph_snapshots.revised | Select-Object status,revision,sourceFile
```

预期status=PASS、stage=G3、graph_built=True，修订图revision=4，vendor_calls=0，own_records_cleaned=True。完整节点、关系和来源在报告的graph_snapshots中，来自真实PG和管理员HTTP接口。脚本结束后会清理临时数据，所以不要到开发库寻找这些工单。

首次克隆、代码变更或环境未准备时，按[图谱接口与完整构建指南](../docs/api/experience-graph.md)先执行迁移、构建和测试。普通启动默认关闭图谱索引；需要显式启用`smartticket.experience.graph-index-enabled`。本轮未自动迁移开发库。回退旧包前停用知识写入和异步知识工作流，保留新增表与数据卷。
