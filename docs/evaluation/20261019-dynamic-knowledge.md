# R05 动态知识验收

日期：2026-10-19。基于已获用户通过并合入 main 的 `0baa65e`，开发分支 `codex/dynamic-knowledge`。本批使用确定性候选模板、本地 BGE-M3 和模型替身，新增厂商调用 **0 次**。

## 实现结果

处理人结单时可填写结构化 solution。工单状态、审计、解决快照、DRAFT 任务和独立知识 Outbox 在同一 MySQL 事务提交；旧请求不填写 solution 保持兼容。取消关闭不会产生成功知识。

候选由确定性模板生成，只有管理员审核、确认脱敏与 SHARED_DEMO 范围后才能发布。审批采用期望版本，任务保存该版不可变问答与哈希。独立队列使用持久消息、确认投递、手动 ACK、有限退避、租约、重放审计和死信。当前每条有长度上限的问答对应一条切片。

嵌入在数据库事务之外计算。PG 事务同时维护发布版本围栏和切片替换；MySQL 另行登记索引回执。检索先排除 PG 非活动版本，再用 MySQL 审核状态和已索引版本校验动态来源。目录故障时动态来源不放行。撤回时无需等待 PG 删除才隐藏来源；较新墓碑阻止旧任务重新发布。

## 复现和限制

完整命令、迁移、开关、审核/重放请求和失败排查见[操作指南](../api/dynamic-knowledge.md)，实现边界见[架构说明](../architecture/dynamic-knowledge.md)。默认关闭工作流，启用前须完成迁移；首版只支持共享演示知识，不支持真实客户数据或私有知识检索 ACL。正则脱敏有限，人工审核仍承担事实及隐私检查。

这是一条合成经验的检索闭环验收，不是生成回答准确率或生产性能测试。未重跑收费的148题生成评测，作者语义复核仍待本人完成；新增独立题评估、长期资源稳定性和本人演示仍属 R06 后续。已经发出的历史回答不因撤回自动消失。进程崩溃导致租约耗尽时可能只有 FAILED 记录而无死信，运维须查询任务表。

本地原始输出在忽略的 `.tmp/knowledge-unit-verified.log`、`knowledge-all-integration.log`、`knowledge-python.log`、`knowledge-local-smoke.json`。公开记录不包含本机凭据、私有配置或启动日志。
