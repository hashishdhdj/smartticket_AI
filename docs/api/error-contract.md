# HTTP 与错误响应契约

更新：2026-10-19。本次为错误响应的兼容性变更；原有只检查 HTTP 200 的客户端需要调整。业务错误码保持原数值。

成功和明确的业务降级返回 HTTP 200、`code=0`，调用方继续检查 `status`、`degraded`、`needHuman`、`statusReason`。异常则同时使用对应的 HTTP 状态与非零业务码。JSON 结构统一为 `code`、`message`、可选 `data`；错误不带 `data`。

| 场景 | HTTP | 典型业务码 |
|---|---|---|
| 参数/类型/请求体错误 | 400 | 40000 / 40001 |
| 未认证/无权访问 | 401 / 403 | 40100 / 40300 |
| 工单不存在 | 404 | 10003 |
| 状态非法、版本冲突、确认过期 | 409 | 10001 / 10005 / 10011 / 10012 |
| 限流、预算异常 | 429 | 42900 |
| 未预料的系统异常 | 500 | 50000 |
| 通过异常表达的模型/向量库不可用 | 503 | 原能力错误码 |
| Spring 路由/方法/媒体类型错误 | 404 / 405 / 415 | 40000 |

例如模型不可用时，分析接口通常返回有效的降级对象；这属于可理解的业务结果，不因为模型不可用一律抛 503。客户端不能把 HTTP 200 理解为 AI 已完成业务目标。

MVC 错误由 `GlobalExceptionHandler` 统一处理；认证过滤器不经过 MVC 异常链，但使用相同的 `Result.fail()` 工厂。错误中不返回堆栈、SQL、密钥或模型原文。框架错误保留适用的 HTTP 头，如 405 的 Allow。
