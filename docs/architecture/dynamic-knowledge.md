# 动态知识闭环设计

2026-10-19。基于已验收 main `0baa65e`，在 codex/dynamic-knowledge 实施。

解决请求新增可选 solution；旧 remark 与状态流转保持兼容。仅提供完整 solution 时，同一工单事务记录结构化解决快照、DRAFT任务和专用Outbox。消息只传标识及版本。消费者按确定性模板生成候选，不调用生成模型。关闭工单不等于产生成功经验。

知识候选仅管理员可审核。发布必须提交经审核的问答、SHARED_DEMO适用范围、明确脱敏确认及期望版本；拒绝和撤回有独立操作与审计。首版只发布合成工单演示知识，不支持真实客户数据或私有知识检索ACL，也不自动认可模型提炼内容。

MySQL记录候选与任务状态，PG记录向量及发布版本围栏；二者各自使用短事务，嵌入在事务之外。版本来源键为 resolved-ticket/候选UUID/v版本.md；PG发布目录保留撤回墓碑，迟到版本不能覆盖新版本。检索先过滤PG非活动版本，再校验MySQL的审核状态与已索引版本；目录不可用时动态来源失败关闭。撤回提交后的新检索不会因PG清理延迟重新返回旧来源；已发出的历史答复不追溯撤销。

默认关闭此工作流；启用须先应用MySQL05与PG02迁移，再设置 smartticket.knowledge.enabled=true 和 async-enabled=true。本地验证使用隔离中间件、模型替身和本地BGE-M3，无新增付费模型调用。
