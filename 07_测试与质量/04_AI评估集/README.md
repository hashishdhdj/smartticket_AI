# RAG 问答评估集

`07_测试与质量/04_AI评估集` 下存放 AI 效果的评估数据。
本文件说明 `RAG问答评估集.csv` 的**字段语义与判定规则**——不说明清楚，这份数据无法被程序或人正确使用。

> 依据：`01_项目说明/项目章程.md` 阶段2 交付物（`AI评估集 → 07_测试与质量/04_AI评估集`）、
> 阶段2 验收标准（「有至少 20 条评估样本」）。

---

## 一、这份评估集评什么

评的是**第4周做的双路检索（`KnowledgeSearchService.search`）**，回答三个问题：

| 要回答的问题 | 靠哪些字段 | 指标 |
|---|---|---|
| 该命中的查到了吗？ | `query` + `expected_sources` | **召回率 Recall@3** |
| 查到的排在前面吗？ | 同上 | **MRR（平均倒数排名）** |
| 该拒答时会不会硬答？ | `expect=miss` 的负样本 | **拒答正确率** |

---

## 二、字段说明

| 列名 | 取值 | 说明 |
|---|---|---|
| `id` | `Q01`~`Q26` / `N01`~`N06` | 题号。`Q` 为正样本、`N` 为负样本 |
| `category` | 账户问题 / 支付问题 / 功能异常 / 工单流程 / 负样本 | 用于**分主题统计**，不参与判定 |
| `query` | 文本 | 模拟真实工单的用户提问 |
| `query_style` | `literal` / `colloquial` / `negative` | 字面贴近 / 口语化改写 / 语料无对应 |
| `expect` | `hit` / `miss` | **本题应该命中，还是应该拒答** |
| `expected_sources` | `文件#小节标题`，多个用 `\|` 分隔 | 期望命中的来源；`miss` 时留空 |
| `note` | 文本 | 设计意图（为什么这么出题） |
| `reference_answer` | 文本 | **预留列，v1 全部留空**。待「`suggestion` 生成方式」确定后再填 |
| `expected_keywords` | 文本 | **预留列，v1 全部留空**。用于评估答案质量 |

### `expected_sources` 的写法

格式为 `来源文件#小节标题`，与检索返回里的 `sourceFile` / `sectionTitle` 对应：

```text
faq/01-账户问题.md#登录时提示「验证码异常」怎么办
```

**允许写多个（用 `|` 分隔）**，因为语料里存在**同场景的两节**（FAQ 一节 + 历史工单一节），
命中任一条都算对。例如：

```text
faq/01-账户问题.md#如何更换绑定手机号|tickets/01-账户问题.md#原手机号已停用，无法自助更换绑定手机号
```

## 三、判定规则

1. **正样本（`expect=hit`）**：`expected_sources` 中**任一**来源出现在融合结果的 **Top-3** 内，记为命中。
   （Top-3 对应配置 `smartticket.vector.fusion.top-n=3`，是链路的真实返回条数。）
2. **负样本（`expect=miss`）**：若最终被判定为「有把握」（即未标记需人工），记为**误答**；反之记为正确拒答。
3. 判定只看**来源**，不看答案文字——所以 `reference_answer` 留空不影响第 1、2 步。

## 四、选题构成（32 题 = 26 正样本 + 6 负样本）

### 正样本 26 题：**一个小节一题**

语料共 26 个小节（FAQ 17 + 历史工单 9），一节一题，使**召回率的分母干净**。

| 提问风格 | 题数 | 考什么 |
|---|---:|---|
| `literal` 字面贴近 | 12 | 基线：能不能查准 |
| `colloquial` 口语化改写 | 14 | **难点**：双路融合的价值是否体现（如 Q02「我的账号登不进去了」） |

### 负样本 6 题：分两档难度

| 难度 | 题号 | 考什么 |
|---|---|---|
| 主题相近但语料无答案 | N01 ~ N03 | 阈值会不会被「主题相近」骗到（如「如何修改发票抬头」，语料只有「如何申请开具发票」） |
| 完全无关 | N04 ~ N06 | 基线：明显无关的会不会被硬答 |

## 五、编码与读取

- 文件为 **UTF-8 with BOM**（便于 Excel 直接打开不乱码）。
- **用程序读取时必须处理 BOM**：否则表头第一个字段会变成 `\uFEFFid`。
  Java 侧建议读取后去掉首个 `\uFEFF`，或使用 `BOMInputStream`。
