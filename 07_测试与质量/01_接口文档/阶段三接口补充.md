# 阶段三接口补充

默认本机端口8080，所有/api请求加X-API-Key。身份来自服务端凭据映射；兼容保留的creatorId/operatorId请求字段不决定权限或审计人。

## 读取本机凭据并创建工单

在ticket-service目录的PowerShell窗口执行，不打印token：

```powershell
$stageToken=(Get-Content '.\phase3-local.properties' | Where-Object { $_ -like 'smartticket.phase3.users[0].token=*' } | Select-Object -First 1).Split('=',2)[1]
$stageHeaders=@{'X-API-Key'=$stageToken}
$stageBody=@{title='支付失败';description='付款后订单未更新';creatorId=100;priority='HIGH'} | ConvertTo-Json
$stageCreated=Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:8080/api/tickets' -Headers $stageHeaders -ContentType 'application/json; charset=utf-8' -Body ([System.Text.Encoding]::UTF8.GetBytes($stageBody))
$stageId=$stageCreated.data.id
Invoke-RestMethod -Uri "http://127.0.0.1:8080/api/tickets/$stageId/analysis" -Headers $stageHeaders
```

刚创建可见PENDING/RUNNING；结束后SUCCEEDED或DEGRADED，suggestion单独保存。失败FAILED，旧输入STALE，未请求NOT_REQUESTED。degraded规则建议包含source_type=RULE，并保留原因。

## Agent与确认

POST /api/agent/runs：请求体`{"message":"查询123号工单并检索处理办法"}`。返回runId、status、answer、needHuman、模型/工具次数、Token、steps、evidence。来源/提案在evidence中。部分工具失败PARTIAL，预算/模型不可用等STOPPED，均需人工处理。

只有管理员可提出指派，处理人必须为配置中的HANDLER。prepareAssignTicket返回actionId、ticketId、assigneeId、expectedVersion、summary和300秒有效期，当前不执行。

POST /api/agent/actions/{actionId}/confirm：同账号管理员明确确认，不接受模型生成的“已确认”字段；重复确认返回原结果。过期/版本冲突409，跨账号或权限不足403。

## 管理员重放与指标

POST /api/tickets/{id}/analysis/replay：管理员凭据，额外Idempotency-Key头使用UUID。同账号同键稳定返回同taskId，同键不同工单409。新请求键在当前任务活跃时复用该任务，终态时创建新generation。

GET /api/admin/metrics：管理员读取Micrometer meters与任务/Outbox状态分布。计数和耗时不是吞吐量或P95压测结果。

## 错误与额度

401缺失/错误凭据；403无对象权限/非管理员；409并发/过期/幂等冲突；429频控或额度不足。响应保持code/message结构，业务状态机错误沿用原业务错误码。模型降级可返回code=0，但必须读取degraded或needHuman，不能按HTTP200判断已得到AI答案。

没有配置模型时可以验证工单异步和规则兜底，Agent会STOPPED。想验证真实工具选择需启用支持tool calling的模型；当前工程验收通过本地HTTP厂商替身完成，不依赖真实付费调用。
