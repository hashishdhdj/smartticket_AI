# RAG 知识库语料

## 语料性质（必读）

**本目录下全部内容为演示语料，不是真实业务数据。**

2026-10-14更新：共8份正文、30个小节；04-工单流程与通用问题和05-项目权限与AI处理依据当前项目代码校对，其余为模拟客服场景。模拟平台的政策不代表SmartTicket已实现相应功能。逐节来源登记位于09_项目依赖与资源/03_知识库素材/knowledge-sources.json，不参与检索。正文修订后仍需单独更新向量索引并重新核查检索阈值。

本项目没有可用的真实 FAQ 与历史工单数据。为验证 RAG 链路（切分 → 向量化 → 检索 → 合并）
能够真正跑通并评估效果，必须有可检索的文本；因此这些语料是**按通用客服知识构造**的，
用于让链路有东西可检、有结果可评。

**请勿**把它当作生产知识库内容使用，也**不要**在项目文档里把它描述为"真实数据"。
若将来接入真实 FAQ，本目录整体替换即可——切分与检索代码不依赖具体内容。

## 目录约定

```text
knowledge/
├─ README.md        本文件。说明语料性质与目录约定，不参与切分
├─ faq/             FAQ 文档，每条问答为一个 `##` 小节
└─ tickets/         历史工单样例，每条工单为一个 `##` 小节
```

**切分只扫描 `faq/` 与 `tickets/` 两个子目录**，本文件位于其外，因此不会被当作语料
——这是刻意的目录设计，避免"说明文档被当成知识库内容检索出来"这种尴尬。
（`KnowledgeCorpusLoader` 的扫描根为这两个子目录，不是整个 `knowledge/`。）

## 文件格式要求

切分器按下列约定解析，写新语料时请遵守：

| 约定 | 要求 |
|---|---|
| 文档标题 | 一级标题 `# xxx`，作为该文档的来源标题（元数据），**不进入正文片段** |
| 切片单元 | 二级标题 `## xxx`，**每个小节切出至少一个片段**，小节标题作为片段元数据 |
| 文档前言 | 一级标题与第一个二级标题之间的内容（如本目录各文件开头的语料性质声明）**不参与切分** |
| 每节长度 | 建议 150~500 字。超过 500 字会被继续切分（见决策记录中的切片策略） |
